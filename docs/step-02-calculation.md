# 第二步：让后端算出表达式

这是开发第二阶段的学习记录。最终版本已接入数据库，最终运行方式和接口返回字段请以仓库 README 为准。

## 本次目标

用户发送字符串 `1+2*3`，后端按数学规则算出 `7`，通过 HTTP 返回结果。这个阶段尚未存储历史；下一步会加入数据库。

## 从普通 Python 函数理解

先看 `src/calculator.py` 中对外提供的函数：

```python
calculate_expression("1+2*3")       # 返回字符串 "7"
calculate_expression("(1+2)*3")     # 返回字符串 "9"
calculate_expression("3*-2")        # 返回字符串 "-6"
calculate_expression("0.1+0.2")     # 返回字符串 "0.3"
```

它接收字符串，输出十进制结果字符串。如果输入不符合规则，就抛出 `CalculationError`。此函数不需要 Flask，也不负责数据库，便于单独测试数学规则。

## 第一步：把字符串拆成记号

`tokenize()` 从左到右扫描，只接受数字、四则运算符和括号。空白可以跳过，但不能把 `1 2` 拼成 `12`。

例如 `1+2*3` 会被拆成：

```text
数字 1 → 加号 + → 数字 2 → 乘号 * → 数字 3 → 结束
```

每个记号保存类型、文字和原始位置。字母、下划线、引号等不属于当前数学语言，因此会被拒绝。这里没有执行 Python 代码。

## 第二步：用函数层级表达优先级

解析器按下面的调用关系工作：

```text
expression()  处理加减
    ↓
term()        先处理乘除
    ↓
unary()       处理正负号
    ↓
primary()     读取数字；遇到括号就计算括号内的 expression()
```

这是一种递归下降解析。名字可以稍后记，先理解它如何计算：

对于 `1+2*3`：

1. `expression()` 先调用 `term()`，得到左边的 `1`。
2. 读到 `+` 后，它再次调用 `term()`，读取右边完整的乘除项。
3. 第二次 `term()` 读到 `2*3`，先算出 `6`。
4. `expression()` 最后执行 `1+6`，得到 `7`。

对于 `(1+2)*3`：

1. `primary()` 看到 `(`，重新调用 `expression()`。
2. 括号里的 `1+2` 先得到 `3`。
3. 读到 `)` 后返回，外层 `term()` 继续完成 `3*3`，得到 `9`。

同级运算用循环从左到右计算，因此 `8/2*2` 等于 `(8/2)*2`，结果为 `8`。

## 第三步：处理正负号和错误

`unary()` 在读取数字或括号前处理正负号，因此 `3*-2` 可以识别为 `3*(-2)`。

- `1/0`：计算右操作数后检查为零，返回“除数不能为 0”。
- `1+`：加号后缺少操作数，返回表达式错误。
- `(1+2`：缺少右括号，返回表达式错误。
- `1 2`：第一个数后仍有未使用的数字，判定缺少运算符。
- `2**3`：不属于当前支持的四则表达式，返回错误。

输入长度和括号深度也有限制，避免一次请求无限占用解析资源。

## 为什么用 Decimal

普通 `float` 使用二进制表示小数，一些十进制数不能被精确表示。我们直接从用户的数字文本创建 `Decimal`，让 `0.1+0.2` 返回 `0.3`。

这不表示所有数学结果都能无限精确：本项目用 28 位有效数字，`1/3` 等循环小数会按精度舍入。结果通过 JSON 字符串传输，前端直接显示，避免再次引入浮点转换。

参考：[Python 官方 Decimal 文档](https://docs.python.org/3.12/library/decimal.html)。

## 第四步：接到 HTTP 接口上

`src/app.py` 中的 `calculate()` 大致完成三件事：

```python
payload = request.get_json()                  # 读取前端发来的 JSON
result = calculate_expression(payload.get("expression"))
return {"success": True, "result": result}   # 把结果传回去
```

上面是简化解释；实际代码还检查请求格式、表达式类型并把异常转成统一错误响应。

接口使用 POST，因为客户端需要在请求体中发送表达式。地址栏直接打开 URL 使用 GET，所以不能用地址栏完成这次调用。

## 亲自运行

后端启动后，在另一个 PowerShell 窗口执行：

```powershell
Invoke-RestMethod -Uri 'http://127.0.0.1:5000/api/calculate' -Method Post -ContentType 'application/json' -Body '{"expression":"1+2*3"}'
```

把表达式分别改为下面几项，先预测结果再运行：

| 输入 | 应得到 |
| --- | --- |
| `(1+2)*3` | `9` |
| `3*-2` | `-6` |
| `0.1+0.2` | `0.3` |
| `8/2*2` | `8` |
| `1/0` | HTTP 400，除零错误 |

PowerShell 在非成功状态时会显示请求错误，这属于预期的接口行为。可以先只运行成功案例。

学习检查：为什么 `expression()` 不直接按字符顺序把 `1+2` 先算掉？你可以沿着上面的函数调用关系解释一遍。
